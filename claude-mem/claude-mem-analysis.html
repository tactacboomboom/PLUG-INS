🧠 claude-mem

1. Le décor

Claude Code oublie tout à la fin de chaque session. Cette amnésie est by design — le contexte se réinitialise, les projets recommencent à zéro. claude-mem est la prothèse mémorielle qui corrige ça : un worker local qui observe silencieusement chaque action, compresse avec un LLM, et réinjecte le contexte pertinent à la session suivante.

Le système repose sur cinq primitives : la Session (unité de travail), l'Observation (capture atomique d'un tool-use), le Summary (résumé structuré d'un tour), le Context (ce qui est injecté au démarrage), et le Worker (démon local orchestrateur). Deux couches de stockage : SQLite pour le structuré, ChromaDB pour le vectoriel.

"Persistent Context Across Sessions for Every Agent" — 76.6k étoiles, Apache-2.0, 7 releases en 7 jours.

2. Les règles du jeu

Le cycle de vie s'accroche à cinq hooks Claude Code. Au démarrage de session : le worker se lance et injecte le contexte mémorisé. À chaque message utilisateur : la session s'initialise. Après chaque outil utilisé : une observation est capturée. À chaque réponse de Claude (Stop) : un résumé est généré. Ces hooks sont non-bloquants — si le worker est absent, Claude Code continue sans eux.

La tension principale : le système utilise ta propre clé Anthropic pour les appels LLM de summarize. Ce n'est pas un service externe — c'est un serveur Express local sur 127.0.0.1:37777. Tes données ne quittent pas ta machine (en mode worker local).

⚠️ Chaque réponse de Claude déclenche un appel LLM de summarize. Sur un abonnement Claude, c'est invisible. Sur une clé API facturée à l'usage, chaque tour coûte.

3. Le socle immuable

Cinq invariants ne bougent pas. Le worker est toujours local — aucune fuite externe en mode par défaut. Les hooks ne bloquent jamais Claude Code — exit 0 systématique sur erreur. La DB ne perd jamais de données — queue de messages en attente et retry exponentiel. Les tokens consommés appartiennent à l'utilisateur — sa clé, ses coûts. La licence Apache-2.0 autorise tout usage commercial sans restriction.

✅ Architecture de confianceRien ne part chez thedotmack. Le code est open-source, auditable, local-first.

4. Les leviers de transformation

Le système offre quatre axes de variation majeurs. Le mode runtime : worker local (défaut, stable) ou server-beta (Postgres + BullMQ + Redis, opt-in, pour les équipes). Le provider LLM : Anthropic, OpenAI, ou Google — configurable. Le stockage : SQLite seul ou SQLite + ChromaDB hybride. La disclosure : index compact (50–100 tokens) → timeline → détails complets, selon la précision nécessaire.

La relicence AGPL → Apache-2.0 en v13.0.0 est un signal fort : thedotmack vise l'adoption enterprise et l'embedding dans d'autres outils. La roadmap server-beta montre une ambition au-delà du plugin Claude Code.

Une commande, zéro friction. Le worker s'auto-installe avec Bun si absent. Les hooks se configurent automatiquement dans settings.json. La mémoire commence à s'accumuler dès la première session sans configuration manuelle.

Le nœud de friction principal : la compatibilité Windows. Les hooks utilisent bash — ils tournent via Git Bash sur Windows, mais certains edge cases de paths peuvent poser problème (le code inclut cygpath pour la conversion).

7. L'équilibre du risque

À 76.6k étoiles et une cadence de release quotidienne, claude-mem est l'un des plugins Claude Code les plus adoptés. Le risque de lock-in est réel : le format SQLite est custom, la migration vers un autre système de mémoire demanderait un export manuel. La dépendance aux hooks Claude Code crée un risque upstream si Anthropic change leur API.

Pour un usage solo comme celui de Yanis, le ratio risque/bénéfice est clairement positif. La mémoire locale, la clé API propre, l'open-source auditable — tous les invariants de confiance sont là. Le combo avec graphify est la vraie valeur ajoutée : claude-mem fournit les observations structurées, graphify en fait de la topologie.

"Le lock-in est dans la DB, pas dans le code. Tant que vous exportez régulièrement les observations, vous gardez la maîtrise."

Points d'attention Windows

⚠️ Paths avec espacesLes hooks bash peuvent avoir des problèmes avec des chemins contenant des espaces (ex: G:\Mon Drive\). Encadrer les paths avec des guillemets dans les commandes.
⚠️ Port 37777Vérifier qu'aucun autre processus n'utilise le port : netstat -ano | findstr 37777
✅ cygpath intégréLe code inclut une conversion cygpath automatique pour les paths Windows dans les hooks bash. Fonctionne avec Git Bash sans configuration supplémentaire.

Matrice Use Cases

✅ OUI — Agent solo multi-sessions

Yanis qui travaille seul sur plusieurs projets en parallèle. claude-mem maintient le contexte de chaque projet entre sessions.

✅ OUI — Combo avec graphify

Les observations structurées (facts, concepts, narrative) sont exactement le format attendu par graphify pour construire un knowledge graph.

✅ OUI — Continuité projet longue durée

Sur des projets comme khaldoun ou Claire qui s'étendent sur plusieurs semaines, la continuité de contexte est critique.

✅ OUI — Abonnement Claude Code Max

Sur abonnement illimité, le coût tokens des résumés est absorbé. Le ratio valeur/coût est maximal.

❌ ATTENDRE — Server-beta en production

Le mode server-beta (Postgres + Redis) n'est pas encore stable. Rester sur worker local.

❌ NON — Clé API pay-per-token intensive

Si vous payez à l'appel API, chaque résumé de session s'accumule. À évaluer selon volume.

❌ ATTENDRE — Données confidentielles sensibles

Même en local, les observations sont en clair dans SQLite. Utiliser les balises <private> pour exclure le contenu sensible.

❌ NON — Équipe multi-dev (sans server-beta)

Le mode worker local est mono-utilisateur. Server-beta requis pour le partage d'équipe, mais instable.
