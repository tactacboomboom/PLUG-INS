🕸️ graphify

1. Le décor

Un codebase, c'est un texte. Des milliers de fichiers qui s'appellent les uns les autres, se référencent, se contredisent parfois — mais dont personne ne voit la structure globale. graphify est la machine qui lit tout ça et vous rend un graphe : les concepts comme nœuds, les relations comme arêtes, les communautés comme clusters colorés.

L'entrée est multimodale — code Python, TypeScript, Go, Rust, PDFs, images, vidéos, URLs. La sortie est universelle — un graph.html interactif, un graph.json requêtable, un vault Obsidian, un wiki agent-crawlable. Avec 49k étoiles et un pipeline en 7 étapes pures, c'est l'outil de cartographie cognitive le plus adopté de l'écosystème Claude Code.

"Turn any folder of code, SQL schemas, R scripts, docs, papers, images, or videos into a queryable knowledge graph." — 71.5x de réduction de tokens revendiquée.

2. Les règles du jeu

Le pipeline suit un ordre strict et immuable : détecter → extraire → construire → clustériser → analyser → rédiger → exporter. Chaque étape est une fonction pure qui ne partage aucun état avec les autres. Les données transitent via des dictionnaires Python et des graphes NetworkX.

La tension principale du système : l'extraction a deux vitesses. Le parsing AST via tree-sitter est déterministe et rapide. L'extraction sémantique via Claude (vision, inférence) est probabiliste et coûteuse en tokens. Les arêtes INFERRED et AMBIGUOUS sont le produit du LLM — les EXTRACTED viennent du code lui-même.

⚠️ Une arête INFERRED n'est pas une vérité — c'est une hypothèse de Claude. Le flag de confiance est la clé de lecture du graphe.

3. Le socle immuable

Cinq invariants structurent le système. Toutes les arêtes ont un type de confiance — aucune relation sans label EXTRACTED, INFERRED, ou AMBIGUOUS. Le cache SHA256 garantit qu'un fichier non modifié n'est jamais retraité. Tout le processing est local — aucun serveur externe requis sauf Claude pour la sémantique. NetworkX est la représentation intermédiaire unique. Tous les outputs atterrissent dans graphify-out/.

✅ Avantage cléMIT license + processing local + formats ouverts (GraphML, Neo4j Cypher, JSON). Zéro lock-in. Vous pouvez exporter le graphe et l'utiliser dans n'importe quel autre outil.

4. Les leviers de transformation

Le mode --mode deep active l'inférence agressive — plus de nœuds, plus d'arêtes INFERRED, plus de tokens consommés. Le mode --update recalcule uniquement les fichiers modifiés (cache SHA256). Le mode --watch rebuildait automatiquement sur chaque commit. La community detection via Leiden (algorithme de graspologic) regroupe les nœuds en clusters thématiques — c'est là que la topologie devient lisible.

Le MCP server stdio expose trois fonctions de requête directement dans Claude Code. L'export wiki (v0.1.7) génère un site agent-crawlable avec wikilinks entre communautés — idéal pour le combo avec claude-mem.

7. L'équilibre du risque

Le projet est jeune en version (0.1.14) mais massif en adoption (49k étoiles en quelques semaines). La maturité algorithmique est réelle — NetworkX + Leiden sont des bibliothèques académiques éprouvées. Le risque principal est la dépendance à Claude pour l'extraction sémantique : chaque fichier non-code (image, PDF) consomme des tokens. Sur un corpus de conversations comme le projet TDA de Yanis, l'extraction peut devenir coûteuse.

Le combo claude-mem + graphify est la proposition de valeur centrale : claude-mem accumule les observations structurées (facts, concepts, narrative) par session, graphify les transforme en graphe navigable. C'est une mémoire à deux couches — temporelle dans la DB SQLite, topologique dans le graphe.

"claude-mem = mémoire temporelle. graphify = mémoire topologique. Ensemble : un knowledge graph vivant qui grandit avec chaque session."

Usage dans Claude Code

# Analyser le dossier courant
/graphify .

# Mode deep (inférence agressive, plus de tokens)
/graphify ./src --mode deep

# Update incrémental (seulement fichiers modifiés)
/graphify . --update

# Watch mode (rebuild auto sur commit)
/graphify . --watch

# Requêter le graphe existant
/graphify query "quelles sont les dépendances de X ?"

# Ajouter une URL externe
/graphify add https://example.com/doc.pdf

Formats d'export

# Générer le wiki agent-crawlable
/graphify . --wiki

# Export GraphML (pour Gephi, yEd)
/graphify . --format graphml

# Export Neo4j Cypher
/graphify . --format neo4j

# Export SVG
/graphify . --format svg

Post-commit hook (watch automatique)

# Installer le hook git
graphify hook install

# Désinstaller
graphify hook uninstall

❌ NON — Scripting automatisé sans version fixée

API v0.1.x instable. Ne pas scripter en CI/CD sans pip install graphifyy==0.1.14 explicite.

❌ ATTENDRE — Graphes > 1000 nœuds en prod

NetworkX en mémoire + render vis.js côté client. Scalabilité pas encore validée sur très grands corpus.

❌ NON — Remplacement d'une vraie DB graphe

graphify est un outil d'exploration/visualisation, pas Neo4j. Pour des requêtes graph complexes en prod, exporter vers Neo4j.
